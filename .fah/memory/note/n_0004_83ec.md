# Note: n_0004_83ec

Java dm.ai alias truth (from fresh clone 4a3719c6, generated MCPToolRegistry/Executor + McpCliHandler + JobJavaScriptBridge): (1) Tool-level aliases exist ONLY as registry metadata — 11 tracker_* aliases each carried by a jira AND an ado canonical tool: get_ticket[jira_get_ticket|ado_get_work_item], search[jira_search_by_jql|ado_search_by_wiql], get_comments[+], post_comment[+], assign_ticket[jira_assign_ticket_to|ado_assign_work_item], move_to_status[jira_move_to_status|ado_move_to_state], link_tickets[jira_link_issues|ado_link_work_items], create_ticket[jira_create_ticket_basic|ado_create_work_item], download_attachment[jira_download_attachment|ado_download_attachment], get_user_by_email[jira_get_account_by_email|ado_get_user_by_email], get_my_profile[jira_get_my_profile|ado_get_my_profile]. Plus 20 source_code_* aliases (gitlab github carriers). (2) resolveToolAlias runs ONLY in McpCliHandler (CLI) — picks candidate by env DEFAULT_TRACKER / DEFAULT_SOURCE_CODE (lowercase integration name), falls back to FIRST candidate with warning. JS bridge does NOT resolve tool aliases and does NOT expose alias globals — MCPSchemaGenerator has zero tracker_ occurrences; JobJavaScriptBridge.exposeMCPToolsUsingGenerated exposes canonical names only. Agent scripts therefore cannot call tracker_* on Java. (3) Param-level aliases ARE honored by the generated MCPToolExecutor in both paths: e.g. jira_search_by_jql.jql aliases [searchQueryJQL, query]; ado_search_by_wiql.wiql aliases [jql, query]; ado_* id aliases [key]; ado_assign_work_item.userEmail aliases [accountId]; ado_move_to_state.state aliases [statusName]; ado_create_work_item.workItemType aliases [issueType], title aliases [summary]. Jira-shaped args are the lingua franca. (4) DEFAULT_TRACKER values: jira/ado (di/TrackerModule), lowercase+trim.
