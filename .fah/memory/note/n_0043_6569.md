# Note: n_0043_6569

The dark-factory merge loop switched to GitHub ISSUES as the tracker in BOTH repos (2026-09-08, owner decision) — Jira retired from the trigger path: issue labeled pr_approved → linked PR (Closes #NN in body or NN-… branch) → merge only when branch protection reports CLEAN → squash → label removed → issue commented. github.token suffices (no Jira/PAT secrets needed for the trigger). fa (IstiN/flutter_agent_harness): main protected (required: Quality gates + JS engine integration (quickjs-ng) + Binaries smoke gate, strict, enforce_admins=FALSE because the auto-release bot pushes version bumps to main via the admin RELEASE_PAT; forced/deletes off), MERGE_TRIGGER_ENABLED=true. dmtools-dart: protected with enforce_admins=TRUE (releases push tags, not main), same fuse. Machine-kit lives in epam/dmtools-dart machine-kit/ (templates merge-trigger-issues.yml + auto-update-prs.yml, setup.sh two phases: workflows → PR, protect → protection+fuse). Gotchas encoded in fa ci.yml: (1) head-pipe in smoke steps = SIGPIPE under pipefail; (2) aggregate gate jobs must pass 'skipped' (PR-only matrix does not run on push/schedule — otherwise every push to main goes red); (3) plain-scalar run: values cannot contain ': '. Release PAT_TOKEN for auto-update-prs re-triggering CI on refreshed branches still recommended (github.token pushes don't trigger workflows).
