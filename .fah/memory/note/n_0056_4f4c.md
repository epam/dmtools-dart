# Note: n_0056_4f4c

fa runner VARIATIONS pattern (dmtools-dart PR #18, user-approved design): provider variation per runner happens ONLY at the env-variables level — Java-parity job override path. Each runner job JSON (machine-kit/teammate-install/runners/*.json) pins FA_PROVIDER_TYPE + FA_PROVIDER_CONFIG in params.envVariables; keys are NEVER in configs — they live in machine-kit/teammate-install/dmtools.env (git-ignored, injected into cli_execute_command subprocesses; job override beats dmtools.env). runners/run-fa.sh = generic CliAgent runner: validates declaration, fail-fasts on missing key (or _BASE64 twin), prompt from arg/input-ticket.md/stdin, session dmtools-<FA_RUN_NAME> under ~/.fah/dmtools-sessions. Ready runners: fa-code-zai.json (zai glm-5.3-flash, https://api.z.ai/api/coding/paas/v4) and fa-review-kimi.json (kimi kimi-k3-256k, https://api.kimi.com/coding/v1). dmtools.env holds ZAI_API_KEY + KIMI_API_KEY placeholders + manual-run default (zai glm-5.3-flash). Roles-based ~/.fah/config.yaml merging was considered and REJECTED — env-per-runner is the chosen mechanism. New runner recipe: copy a runner JSON, change contextId/FA_RUN_NAME/FA_PROVIDER_TYPE/FA_PROVIDER_CONFIG/model; declare the key name via apiKeyEnvVar.
