# Note: n_0057_4873

fa runner variations FINAL design (dmtools-dart PR #18 @ 18dfb79, owner-approved): NO custom runner engine (run-fa.sh deleted) — runners are thin INHERITED configs over real dmtools-agents agents via the Java-parity parent mechanism: {"parent":{"path":"../../../agents/X.json"},"params":{"metadata":{"contextId":...},"envVariables":{AI_AGENT_PROVIDER:fa, FA_PROVIDER_TYPE, FA_PROVIDER_CONFIG}}}. Deep-merge keeps parent env keys (verified with real RunCommandProcessor: fa-review-kimi ← pr_review keeps CLI_ALLOWED_COMMANDS; fa-code-zai ← bug_development). Workflow-level KEY SEPARATION via apiKeyEnvVar naming: each runner names its own key (ZAI_CODE_KEY / KIMI_REVIEW_KEY), values only in git-ignored machine-kit/teammate-install/dmtools.env; shared ZAI_API_KEY/KIMI_API_KEY = manual-run fallback. Dependency: dmtools-agents PR #352 (providers/fa.sh + AI_AGENT_PROVIDER=fa) must merge before runners work end-to-end. New variation recipe: copy a runner JSON, swap parent agent + contextId + provider/model/key-name — no engine code ever.
