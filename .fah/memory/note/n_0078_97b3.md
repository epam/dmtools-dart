# Note: n_0078_97b3

fa session persistence wired into ai-teammate-issues.yml (dmtools-dart PR #18 @ aade71a, answer to owner's "fa will restore sessions correctly?"): run-agent.sh → fa-session.sh builds deterministic named session fa-<repo>-<key>-<group>-<hash8> passed as fa --session/--session-root (resume-or-create). Group from AI_TEAMMATE_CONFIG_FILE (parent agent config): bug_development/story_development/pr_rework → dev-write (rework RESUMES the ticket's dev conversation), pr_review → dev-review. Key = AI_TEAMMATE_DISPLAY_KEY = GH-<issue number> (matches TeammateJob contextId). Cross-run persistence via actions/cache@v6: export-keys step runs `bash agents/setup/cache.sh keys fa-session` (writes FA_SESSION_CACHE_PATH/KEY/RESTORE_KEY to GITHUB_ENV via export_var), immutable run-scoped key -v1-<run_id>, restore-keys prefix for previous runs, post-job save automatic; session dir <workspace>/.dmtools/fa-sessions (git-excluded by fa-session.sh). Guard outputs config (runner→agents/<agent>.json mapping). Java dm.ai does NOT set AI_TEAMMATE_* — the contract is env-driven by the workflow. Dart CliAgent propagates process env to cliCommands (cli_agent.dart ..addAll(Platform.environment)). Gotcha: python heredoc strings containing bash lines ending in " collide with """ — use ''' quoting.
