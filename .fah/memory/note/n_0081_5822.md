# Note: n_0081_5822

gh-71 bounded the ai-teammate review loop (dmtools-dart .github/workflows/ai-teammate-issues.yml): (1) auto-rework rounds per issue are counted via rework-round-<n> labels (highest n wins); after MAX_AUTO_REWORK_ROUNDS (workflow env, repo-var overridable, default 2) consecutive rounds without APPROVE the verdict step labels needs-human + posts unresolved PR review threads (GraphQL via review-verdict.sh threads) instead of agent:rework — human fixes or re-labels agent:rework to re-arm (escalation cleared the counter → fresh cap); APPROVE also clears the counter. (2) Verdict is resolved JSON-first from outputs/pr_review.json (fallback = legacy token grep of run output) and REQUEST_CHANGES with issueCounts.blocking==0 is honored as approve (approve-with-suggestions). Decision logic lives in machine-kit/teammate-install/scripts/review-verdict.sh (pure, eval-safe key=value output, unit-tested in test/machine_kit/review_verdict_test.dart); fa-review-kimi.json appends machine-kit/teammate-install/instructions/review-verdict-rules.md to reviewer prompts via the parent-config "merge": ["params.cliPrompts"] directive — RunCommandProcessor._ParentConfigResolver deep-merges child onto parent and concatenates arrays at merge paths, so machine-kit runners can extend submodule agent prompts without touching the agents/ submodule. Supersedes the n_0077 note's "manual re-review for now" rework-loop description.
