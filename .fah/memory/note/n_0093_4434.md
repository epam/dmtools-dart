# Note: n_0093_4434

Machine e2e gotchas (GitHub workflows, issue→dev→review→rework→merge chain), all fixed on main as of 2026-09-09:
1. dmtools CLI dispatches on args[0] — flags (--debug) must come AFTER the command; trailing --key value pairs land in params (RunCommandProcessor parses JSON values, so --metadata '{"contextId":"gh-N"}' works).
2. Workflow steps without a checkout must pass --repo "$GITHUB_REPOSITORY" to every gh call (guard job died on 'not a git repository').
3. Workflow permissions need issues:write for link-back comments; label/comment events created with GITHUB_TOKEN do NOT trigger other workflows — use the SOURCE_GITHUB_TOKEN PAT for cross-workflow triggers (handoff agent:review label), or relabel from a user token.
4. PRs authored by the bot need maintainer approval for CI (runs sit in action_required): approve via gh api -X POST repos/OWNER/REPO/actions/runs/<id>/approve. Auto-update-prs merges main into PR branches with GITHUB_TOKEN → no CI on the new head → push an empty commit from a PAT to retrigger.
5. Review→PR matching (githubHelpers._scorePR) matches ticket key vs PR title/branch. The issue flow uses shared contextId gh-<issue> (passed via --metadata) so the dev branch ai/gh-<issue> matches the review key gh-<issue>. pr_review.json APPROVE is overridden to REQUEST_CHANGES unless customParams.allowApproveWithSuggestions=true (set in fa-review-kimi.json).
6. Kimi coding API model id is 'k3' (not kimi-k3-256k; the API 401s with a hint). Agent CLI failures print diagnostics on stdout — cli_execution_helper buffered path now includes stdout under 'Output:' on failure.
7. Branch protection on main: required checks quality+agents-suite, strict up-to-date, enforce_admins. Merge-trigger fires on Quality workflow_run AND issues:labeled pr_approved; PR↔issue linkage accepts 'Closes #n' bodies, '<n>-' and 'gh-<n>' branch patterns.
