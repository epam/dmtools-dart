# Note: n_0217_549d

GitHub SM-factory live-verified platform facts (2026-09-20, IstiN/flutter_agent_harness machine-kit #687): (1) github-actions[bot] CANNOT update PR branches through ANY GitHub API — GraphQL updatePullRequestBranch (gh pr update-branch) is denied regardless of token scopes (PullRequests:write, +Contents:write all tried), and REST /pulls/{n}/update-branch is PUT-only (PATCH→404) yet still 403s the bot with "user doesn't have permission to update head repository". A PAT gets 202 on the same PUT. (2) The ONLY working silent-update path for the Actions bot: `gh repo clone TARGET /tmp/dir -- --no-tags --single-branch --branch B --depth 200` → `git fetch --no-tags --depth 200 origin main` → `git merge --no-edit FETCH_HEAD` (with -c user.name/email) → `git push https://x-[REDACTED_SECRET] B` (anonymous clone has no push creds — "could not read Username"). The job cwd is the dmtools-agents ENGINE checkout, not the target repo — git commands there fetch the wrong repo. (3) Landed in dmtools-agents #453/#455/#456/#457 (silentUpdateBranch/patUpdateBranch in smAgent.js); fah repin chain #714→#723. Final live result: 5/5 branches updated by SM tick, processed:5. Nuance: the update pushes DID fire pull_request CI runs (GH_TOKEN in the cli child env likely resolves to a PAT — SILENT_GH_TOKEN secret or dmtools.env chain), so "no CI" is aspirational; fresh checks help the merge flow (BLOCKED resolves), acceptable.
