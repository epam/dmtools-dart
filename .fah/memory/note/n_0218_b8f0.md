# Note: n_0218_b8f0

Machine loop redesign 2026-09 (owner token-budget rule; dmtools-agents#477 → b26509b2, dmtools-dart#193, fa#770): (1) DISPATCH-ONLY CI — pushes fire no CI; the SM is the only trigger via `gh workflow run <ciWorkflow> --ref <branch>` (smAgent validate_pr; per-repo knob rule.ciWorkflow > jobParams.ciWorkflow > 'quality.yml'; factory-sm input ci-workflow, fa passes ci.yml, dmtools-dart default). target quality.yml/ci.yml: pull_request trigger removed, workflow_dispatch added, push main kept for badges; required checks still match (dispatched runs register check runs on the head SHA). (2) LATCHES: ai_dev_started (dev leg once), ai_validated (first green CI — NEW rule validate-fresh dispatches on heads with checks:'none'; validated-green/merge_pr latch it), pr_approved STICKY (fail_validation no longer unarms — supersedes fa pr-750 fix; merge_pr verifies pr_approved ON THE PR, un-approved green latches ai_validated instead of merging; review-after-dev requires prLabels:[ai_validated]+green; review-stale-verdict/review-threads-resolved never re-arm approved PRs). Loop: dev→validating⇄rework until ai_validated; then rework⇄review until pr_approved; then rework→validate→merge with NO re-review. auto-update-prs.yml deleted in both target repos (SM silent-update-behind owns freshness; PAT-for-synchronize dance retired). Transition gotcha: PRs changing the trigger get no push-CI — dispatch manually (gh workflow run <wf> --ref <branch>), which is exactly what the SM does post-merge.
