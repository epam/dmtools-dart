# Note: n_0222_6c61

runAsync/wait parallel-JS design (epam/dmtools-dart#224, [wip]): cross-runtime API — must land in BOTH Dart (worker isolates, each own [REDACTED_SECRET]+PropertyReader snapshot; wait() parks on native_synchronization Mailbox.take()) and Java dm.ai (one GraalJS Context per JobJavaScriptBridge, thread-confined → worker thread owns its bridge; wait() = Future.get()). Java verification facts: JavaScriptExecutor.execute() news a fresh bridge per run; PropertyReader overrides are ThreadLocal (PropertyReader.java:29 THREAD_LOCAL_OVERRIDES) → Java worker must snapshot parent overrides onto its own ThreadLocal. JSR stack ownership: engine = IstiN/quickjs_runtime (direct git dep of dmtools-dart: QuickjsRuntime, registerHostFunction, executePendingJobs exists but unused); flutter_js_widget_runtime (pub: js_widget_runtime) is the Flutter widget layer ON TOP of quickjs_runtime, not on dmtools-dart's path — both owner-owned; cloned at ~/git/flutter_js_widget_runtime. Option A (issue #224) touches neither jsr repo; Option B (promise/await via executePendingJobs pump) = engine-level project in quickjs_runtime, feasible with a developer.
