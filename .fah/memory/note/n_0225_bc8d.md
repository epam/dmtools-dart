# Note: n_0225_bc8d

runAsync pooling LIVES IN quickjs_runtime (owner decision 2026-09-23: engine-level feature, not dmtools host code). IstiN/quickjs_runtime PR #2 (branch feat/async-engine-pool, v0.2.0): AsyncEnginePool owns worker isolates + handshake + dispatch/wait mailbox + FIFO backpressure + fire-and-forget cache + dead-worker completion + asyncJobPrelude/asyncWorkerBootstrap consts + runAsyncJobOnRuntime helper + attachMainRuntime. Consumer owns worker body: top-level AsyncWorkerMain(AsyncWorkerLink link) — MUST be top-level/static (Isolate.spawn entry; function reference crosses via a record in the spawn message); or simpler executor-style hook. dmtools-dart PR #226 (commit 1d46ec4) = thin adapter: worker body boots per-worker SyncHttpBridge + fresh wireEngine'd runtime per job; dispatch context = params/dirs + PropertyReader override snapshot; async_prelude.dart deleted (re-export from package). pubspec ref: feat/async-engine-pool until merge+tag. GOTCHA: a fresh pub-cache checkout of the jsr branch has NO prebuilt libquickjs_bridge.so — worker isolates die on dlopen and wait() parks forever (silent hang; `make native` fixes). Java side: epam/dm.ai#587 keeps host-level threads on GraalJS (owner's split).
