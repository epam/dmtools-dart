# Note: n_0226_cb9d

node/js compat layer in quickjs_runtime (issue #3, PR #4 branch feat/node-compat): installNodeCompat(rt, NodeCompatConfig) — Tier 1 real: global alias, console (sink hook), process (env/cwd/exit hooks), posix path, assert, util, TextEncoder/Decoder (utf8 host hooks), atob/btoa, performance.now (clock hook), crypto.randomUUID/getRandomValues (random hooks), structuredClone (JSON), require() = builtins(path/assert/util) + installNodeCompatModule registry + fallback to pre-existing loader. Tier 2 typeof-safe call-time stubs with alternatives: Buffer, fetch, AbortController, setTimeout/setInterval/setImmediate, process.nextTick. FULL BRIDGE MARSHALING CONTRACT (both halves, verified in quickjs_bridge.c): JS->host single arg = bridge JSON-stringifies THE VALUE as-is (multiple args = array, none = {}), so JS passes RAW values — pre-stringifying double-encodes; host->JS results are JS_ParseJSONd into real values — never JSON.parse them again (silent degrade to defaults if you do; swallowed try/catch hides it). Owner motivation: AI-written agent scripts hit bare ReferenceErrors on node idioms — compat layer makes failures self-explanatory. dmtools-agents corpus evidence: node APIs only in Node-run files (js/test/*.test.js, node_testRunner.js) — additive, not parity debt. Follow-up: dmtools-dart wires installNodeCompat into engine wiring (separate PR; needs owner sign-off as additive surface).
