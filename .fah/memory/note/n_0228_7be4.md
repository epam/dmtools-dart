# Note: n_0228_7be4

Cross-runtime conformance (2026-09-23): one byte-identical fixture test/fixtures/cross_runtime_conformance.js (sha256-verified copies) runs in all three runtimes — quickjs_runtime (PR IstiN/quickjs_runtime#5, warm-worker runAsync), dmtools-dart (PR epam/dmtools-dart#226, spawns real bridge engines with nodeCompat), Java dm.ai (PR epam/dm.ai#587, GraalJS bridge). Same expected-result object in all three: tier-1 compat (process/[REDACTED_SECRET]/structuredClone), tier-2 typeof-safe stubs, runAsync(fn).wait()/runAsync.all with compat used INSIDE the dispatched fn. Catches: (1) GraalJS Value.toString() is a debug display string that TRUNCATES long function sources with '...<omitted>...' — runAsync DispatchProxy was corrupted for long fns; fixed by stringifying fn.toString() in JS prelude (both Dart+Java preludes) and requiring a string arg; short fns fit under the truncation limit so 10/10 unit tests missed it. (2) quickjs_runtime warm-worker race (documented in its test): warm engine at pool start + main-engine eval INSIDE a host callback → async engine silently sees undefined globals (native-scope timing), tests guard with runAsync(...).wait() before in-eval dispatches. nodeCompat knob adopted: params.jobParams.nodeCompat === true wires installNodeCompat into main AND worker engines (dart engine_factory.dart wireEngine; Java JobJavaScriptBridge main + runAsyncJob), default-off.
