# Note: n_0236_4507

dmtools-dart crap4dart gotcha: the `test_assertions` gate counts expect() calls LEXICALLY inside each test() callback body. Extracting test bodies into helper functions makes the gate see "0 assertions" and fail (max 3 allowed bare). Working pattern when main() exceeds method_size (60 lines): move the test() registrations WITH their assertion-bearing bodies into top-level group functions (e.g. `void _xTests(AsyncJobPool Function() pool) { test('...', () { ...expect... }); }`), main() just calls the groups; pass late/shared fixtures as `T Function()` getters so setUp-initialized values resolve lazily. Always run `crap4dart check --staged` (needs `dart pub global activate crap4dart 0.9.5`, PATH += ~/.pub-cache/bin) on test refactors, not just dart analyze. The test_coverage gate fails on fresh worktrees for lack of coverage/lcov.info — that's expected; CI regenerates it before check --all.
