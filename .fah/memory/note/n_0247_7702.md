# Note: n_0247_7702

runAsync contract (quickjs_runtime, verified live 2026-09-28): `runAsync(fn, args)` takes a FUNCTION object as first arg — the runtime re-serializes it via fn.toString() for the worker engines. Passing a string worker source throws "runAsync expects a function as its first argument". JS-side fan-out helpers must eval the string source once and hand runAsync the function. Unit-test fakes must mimic the function contract. Also: runAsync workers are fresh isolates with empty module caches — any per-tick cache state must travel via args (preseed snapshot) AND results must be explicitly written back to the main engine's cache by the caller after wait(); otherwise parallel fan-out re-fetches what sequential already memoized (measured: 20 get_pr parallel vs 6 sequential before write-back).
