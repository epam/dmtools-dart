# Note: n_0248_164f

GitHub reusable-workflow + Actions runtime gotchas proven live on the 2026-09-28 factory migration (each cost one failed dry tick): (1) `secrets:` in a called reusable workflow belongs INSIDE `on.workflow_call`, not top-level — GitHub parses the callee lazily, YAML errors surface only at first dispatch (422 'Unexpected value secrets'). (2) `${{ env.X }}` in a step `env:` block evaluates at JOB START — runtime additions via `$GITHUB_ENV` are invisible to contexts; use the shell variable instead. (3) Step `env:` values are set LITERALLY: bash does no nested expansion, so `ENVVAR: ".../${SHELLVAR}"` keeps a verbatim `${SHELLVAR}` placeholder — export inside the run script instead. (4) Repo Actions variables (`vars.DMTOOLS_VERSION`) outlive refactors — stale pins silently override 'latest' defaults (a v0.1.20 pin masked the pack resolver). (5) `dmtools <tool> <json>` direct invocation needs an authenticated github_* tool catalog; bare `dmtools doctor` in CI is a no-op without credentials. (6) crap4js (IstiN-style) ESM entry-guard `import.meta.url === 'file://'+process.argv[1]` fails on macOS /tmp symlink (/private/tmp) — exit 0 with empty output, no error; use realpath locally (Linux CI unaffected). (7) nyc instruments only .js when copying; rsync non-js payloads separately, and its require hook is bypassed by eval/loadModule harnesses — pre-instrument with `nyc instrument` and dump global.__coverage__ via a wrapper.
