# Note: n_0250_310b

quickjs_runtime native dylib (libquickjs_bridge.so) is NOT built by `dart pub get` — after any quickjs_runtime version bump (e.g. 0.3.5, commit b0d5f2a6) each dev machine must run `bash ~/.pub-cache/hosted/pub.dev/quickjs_runtime-<ver>/tool/build_quickjs.sh` or JS tests fail. CI does this in quality.yml; local runs silently hit it. Symptom of a missing dylib in async_job_pool_test.dart: 13 fast [E] failures, then an INFINITE HANG at 'dispatch/wait roundtrip without a JS engine on the caller' (the only test dispatching to a worker without a main engine first). Fixed the hang mechanism in lib/src/js/async_job_pool.dart (2026-09-29, uncommitted): engine creation moved inside the try + last-resort envelope in the worker loop — worker failures now answer the job with an error envelope instead of killing the isolate while the caller is parked in Mailbox.take(). Also: full-suite local runs need `ulimit -n 8192` (EMFILE at default 256 when several dart test processes run concurrently).
