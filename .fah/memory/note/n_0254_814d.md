# Note: n_0254_814d

fa SM-machine (IstiN/flutter_agent_harness) validation contract (learned 2026-09-30 by keeper-3): there is NO dispatchable validate leg — ai-teammate.yml workflow_dispatch accepts leg only in [dev, review, rework]; `gh workflow run -f leg=validate` returns HTTP 422. Validation = a CI run (ci.yml workflow_dispatch) on the PR head + the SM tick stamping the 3 required checks (Quality gate / JS engine integration (quickjs-ng) / Binaries smoke gate); the machine does this itself when it arms a PR (ai_validating) in the merge window. To unstick a PR stuck at the tail of the fresh queue, dispatch the SAME review leg the SM uses: `gh workflow run ai-teammate.yml --repo IstiN/flutter_agent_harness --ref main -f leg=review -f pr=<n> -f reason="keeper: unstick"`. Fast status source: data/fa-state.json on factory-data branch (lanes: validating/approved_queue/review/fresh, tick.at, tick.dryRun).
