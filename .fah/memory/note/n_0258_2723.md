# Note: n_0258_2723

Machine-loop architecture (owner-confirmed 2026-09-30): dmtools-agents MUST NOT depend on dmtools-dart source — only on its released CLI binary (DMTOOLS_VERSION) at runtime. Artifact flows: dmtools-dart releases → CLI binary (consumed by all); dmtools-agents releases → agent packs zip+catalog.json (consumed by fa/epam via AGENTS_VERSION/DMTOOLS_PACK_REGISTRY). sm_github.json's "repo": "epam/dmtools-dart" is a watch-target parameter (SM scans that repo via GitHub API), NOT a code dependency — the SM loop for epam is served from dmtools-agents' cron (historical dogfood). Frozen SM engine lives in IstiN/dmtools-agentic-workflows@0c19a4f; dmtools-agents = agent code + configs; per-repo stubs (fa's machine-sm.yml) call factory-sm.yml with repo-specific inputs. Pending offer: move epam's SM config into epam repo (like fa does) so dmtools-agents keeps only the pack.
