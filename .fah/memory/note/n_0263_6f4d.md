# Note: n_0263_6f4d

dmtools-agents PR #589 (branch fix/review-verdict-fallback-chain, commit e5450a7, NOT merged — parent coordinates): review-verdict.sh hardened for the gh-305 gap (silent "::warning::no verdict found — skipping labeling" stranded a review cycle). Verdict extraction is now a fallback chain: pr_review.json → run output → PR comments+review bodies → issue comments, then LOUD failure (::error:: + needs-human label + per-source diagnosis comment + exit 1). Comment sources trust machine-written authors only (*[bot] plus MACHINE_AUTHOR env, exact-match). New eval-safe `diagnosis=` output keys: absent/missing/malformed/no-verdict-tokens/hit:<REC> per source. Durable test-pattern discovery: dmtools-agents js/unit-tests CAN execute real bash scripts via the cli_execute_command global when env CLI_ALLOWED_COMMANDS=bash is set (documented dmtools whitelist extension; whitelist check is on the first token only); canonical gate agent-pack-release.yml test step now sets that env so test_reviewVerdict.js (23 cases, hermetic mktemp fixtures inside one bash -c per case) runs there, while it self-skips under the node coverage harness (cli_execute_command undefined = mock-gap precedent). dmtools-dart contract tests (test/machine_kit/review_verdict_test.dart + ai_teammate_review_cycle_test.dart) parse decide output splitting on the FIRST '=' and expect exitCode 0 — additive output keys are safe; they also assert step name, label wiring strings, and the 'bash factory-agents/setup/review-verdict.sh decide' delegation, all preserved. PR Quality+Agent Docs gates green on the branch (runs 36784468176/36784468232).
